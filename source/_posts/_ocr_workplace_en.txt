Agent Skill是 什么?从原理到 使用
Agent Skill将大模型能力封装为可复用模 块。 助力智能体高效执行复杂任务与协作。

Agent Skill = 大模型 Agent 的 「可复用小能 力模块」 用来把"会聊夭的模型"娈成"能办事的智能 体。
先搞清概念: Agent Tool Skill 有啥 区别?
先把三个容易混的词摆在一起:
Agent (智能体)
有目标 有记忆 会自己规划和调用工 具的大模型应用。
比"单轮大模型 API多了决策和执行。
Tool Function (工具/函数调用)
一般指 一个具体能力的底层接口:

更接近"原子操作"。

站在 Agent 层的抽象:
把若千工具+规则 + Prompt 封装成 《对 Agent 来说一键可用的能力单元"。

Agent Skill 的原理: 从「调用函数」到 「组合能力」
1.大模型怎么知道有哪些 Skill?
主流做法是: 把 Skill 作为"可调用选项"暴露 给模型, 并描述清楚:
技能名: query_user profile
功能描述: 用来根据 user_id 查询用户 画像
入参 schema: 需要什么字段。类型是什
返回 schema: 返回数据的结构
使用场景:  什么时候该用这个技能
这些信息在"系统 Prompt 工具列表"里提 供给 Agent。

首先;我们要建立一个直观的认知。
在传统的对话模式里; 模型的能力完全依赖于训练 数据和你当前的 Prompt。 但是 Agent Skills 不 一样; 它是模块化的。
你可以把 Agent Skills 想象成是给 Claude 这 个 "大脑 安装了一个个外部的工具包。这个工具 包里不仅有 说明书" (Instructions), 还有 "工 具 CodelScripts 和 e  参  考  资 料' (Reference Data)
Anthropic 官方给出的定义里; 有一个非常关键的 词: Filesystem-based (基于文件系统)。
这利咱们平肘写的 Python 库非常像。当你 import numpy 的肘候。你并没有把 numpy 所 有的源码都背下来;你只是告诉环境 "我有这个能 力"= Agent Skills 也是同理。它是一组存储在虚 拟文件系统里的文件, Claude 可以像操作电脑一 样去读取。执行这些文件。
这就带来了三个核心优势:

目前 Claude Code 已经 subagent mcp, 为什 么还需要 Skill 呢?  从官方文档已经我自己总结来 看,有以下原因:
1 Skill 是给所有人用的, 而不是只给 developer 用的 , 所以叫 Agent Skill , 而不是 Claude Code Skill。 任何有专业技能的人都可以把技 能沉淀到 Skill 中来让 Agent 调用。 2 Skill 能执行一些精确的操作。 比如生成 PPT, 如果最终要转成 pptx 格式, 这个转换过程脚 本来做是最合适的。

什么是 RLHF
RLHF (Reinforcement Learning with Human Feedback) 是。它-种结合强化学习与人类反馈的技术。主要用于微调 语言模型以使其行为更符合人类的需求或偏好利用人类提供 的反馈数据指导模型优化。生成更符合预期的响应。 为什么要 RLHF?
弥补 SFT 的回答的局限性 在 SFT 阶段, 模型虽然通过标注数据学 会了执行特定任务, 给出符合任务规则 的回答, 但这些回答往往只是正确。却 不一定能满足人类的个性化需求和价值 观。例如。在对话任务中。对于如何减 肥的提问, SFT 后的模型可能只是机械 地罗列减肥方法。不能根据提问者的潜 在需求 (如时间紧迫 不想运动等)  提 供针对性建议。
提高模型综合思考的能力
用户的需求是复杂多样且不断变化的, 很难通过有监督微调阶段的固定标注数 据完全覆盖。
RLHF 具有动态优化的能力。能够根据 实时的人类反馈。综合调整输出,更好 地满足不同场景下的多样化需求。
提升用户体验
对于实际应用中的大模型, 用户体验是 关键。即使模型在任务准确性上表现良 好; 但如果输出的回答冗长 难以理 解 过于生硬规则, 不能满足用户的交 互期望。
RLHF 利用人类对模型输出的偏好反 馈。训练奖励模型。让模型学习到人类 对回答的质量判断标准。模型在生成回 答时。会朝着更受人类欢迎的方向优 化;不仅能给出正确答案。还能以更综 合的符合人类期望的方式呈现。
RLHF 可以让模型学习到人类在交互过 程中的各种偏好, 如回答的简洁性。语 气的友好度 信息的时效性等。

|。默认网关。路由
电脑连上网络后,通常会拿到一个本地 IP; 开了 VPN 或零信任客户端,还会多出一层虚拟 IP。 系 统会先判断:
目标 IP 和我是不是在同一个本地网段。
如果在同-一个网段,数据通常可以直接发过去。 如果不在,就要交给默认网关。
默认网关是兜底的下一跳2 系统没有命中更具体的 路由时。先把包交给它,剩下的交给路由器继续转 发。路由表负责决定:
去某个目标 IP 时,应该走哪张接口
必要时 ,应该交给哪个下一跳
流量不总是走默认网关c 只要路由表里有更具体的 规则,系统就会优先走那条规则。
比如:
default -> en0
10.2.11.117/32 -> utung

这时你访问10.2.11.117,不会走 eno, 会直接走 utung 因为 /32比 default 更具体。
这也是一台机器能同时挂多个网络工具的原因。真 正决定流量归属的,是路由规则。
ARP。 NDP
这一步很底层,但很重要c 路由表告诉系统下一跳 是谁,网卡真正发数据时。还要知道下一跳的二层 标识。IPv4 里常见的是 ARP , IPvG 里常见的是 NDP。 它们解决的问题是:
默认网关的 MAC 是什么
本地网段里某台机器的二层标识是什么
如果这一步出问题,常见现象是:
DNS 看起来正常
路由也没问题
目标就在本地网段
结果还是发不出去

(三) 以斗拱为结构之关键。并为度量单位。 在木构架之横梁及立柱间过渡处, 施横材方木 相互垒叠 前后伸出作 "斗拱" 与屋顶结构 有密切关系。其功用在以伸出之棋承受上部结 构之荷载。转纳于下部之立柱上,故为大建筑 物所必用。后世斗棋之制日趋标准化, 全部建 筑物之权衡比例遂以横棋之 "材"  为度量单 位。犹罗马建筑之柱式(Order)以柱径为度量 单位。治建筑学者必习焉。一系统之建筑自有 其-定之法式。如语言之有文法与辞汇; 中国 建筑则以柱额。斗棋。梁。樽 瓦。檐为其 "辞汇" 施用柱额。斗棋。梁。樽等之法式 为其 "文法" 虽砖石之建筑物,如汉阙。佛 塔等。率多叠砌雕凿。仿木架斗棋形制。斗棋 之组织与例大小, 历代不同,每可藉其结构 演变之序。以鉴定建筑物之年代。故对于斗棋 之认识,实为研究中国建筑者所必具之基础知 识。
